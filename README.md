# По делу — список задач

Небольшое приложение на **React + TypeScript**, созданное с **Vite**. Адаптивный интерфейс на русском языке, без сервера, API и дополнительных UI-библиотек.

Примерное время выполнения: **около 20 минут** на реализацию, структуру, оформление, тесты и настройку публикации.

## Запуск

Нужен **Node.js 24+** и npm. При использовании nvm можно выполнить `nvm use` — версия указана в `.nvmrc`.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, обычно <http://localhost:5173/>.

## Возможности

- Добавление задачи кнопкой или клавишей Enter. Пробелы по краям убираются, пустые и пробельные строки не добавляются. Максимальная длина — 280 символов.
- Переключение статуса через чекбокс или нажатие на текст задачи. Выполненные задачи зачёркнуты.
- Удаление задачи отдельной кнопкой.
- Фильтры «Все», «Активные» и «Выполненные» со счётчиками.
- Сохранение задач и статусов в localStorage после каждого изменения, восстановление при запуске.
- Счётчик оставшихся задач, индикатор прогресса и отдельные пустые состояния для фильтров.
- Адаптивная сетка: на узких экранах блок прогресса располагается под списком. Длинные названия переносятся.
- Управление с клавиатуры, подписи элементов, видимый фокус и поддержка reduced motion.

Данные хранятся только в текущем браузере под ключом `po-delu:tasks:v1`. Между устройствами и вкладками синхронизации нет. Если хранилище недоступно или переполнено, приложение показывает сообщение и продолжает работать в памяти. При повреждённых данных открывается пустой список с предупреждением.

## Структура

Использована FSD с импортами из верхних слоёв в нижние. У слайсов есть публичный API (`index.ts`); компоненты и стили находятся в `ui`, состояние и операции — в `model`.

```text
src/
├── app/                    # Корневой компонент, глобальные стили
├── pages/tasks/            # Страница приложения
├── widgets/task-board/     # Сборка списка, фильтров и прогресса
├── features/
│   ├── create-task/        # Форма и логика ввода
│   └── filter-tasks/       # Фильтры и выбранный режим
├── entities/task/
│   ├── model/              # Типы, операции, хранилище, useTasks
│   └── ui/                 # Представление одной задачи
└── shared/                 # Иконки и общие функции
tests/                      # Тесты доменной логики и хранилища
```

Чистые функции создания, переключения, удаления, фильтрации и подсчёта задач не зависят от React. Работа с localStorage вынесена в отдельный модуль; хук управляет состоянием и сохранением. UI получает данные и обработчики через props. Для такого объёма отдельный state manager и роутер не нужны.

## Проверки и production-сборка

```bash
npm test
npm run build
npm run preview
```

Тесты выполняются встроенным тестовым раннером Node.js: валидация ввода, переключение в обе стороны, удаление, фильтры, счётчики, восстановление, повреждение и ошибки хранилища. TypeScript работает в strict-режиме. Сборка лежит в `dist/`, локальный preview открывается по адресу **http://localhost:4173/test-list/**.

Также доступна команда `npm run lint`.

Автоматические тесты и production-сборка проверены. Визуальная проверка в браузере не выполнена: в рабочей среде недоступен браузерный сервис и не выданы разрешения на управление Chrome.

## GitHub Pages

Для репозитория `Marat-Tibilov/test-list` уже подготовлены `base: '/test-list/'` для production-сборки и workflow `.github/workflows/deploy.yml`. В dev-режиме приложение работает от `/`.

1. Самостоятельно сделайте commit и push в ветку `main`:

   ```bash
   git add .
   git commit -m "Build responsive task list with React and TypeScript"
   git push -u origin main
   ```

2. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**. Другой шаблон workflow выбирать не нужно: файл уже есть в проекте.
3. Откройте **Actions → Deploy to GitHub Pages**. Если первый запуск произошёл до включения Pages и упал, перезапустите его через **Re-run all jobs** или запустите workflow вручную через **Run workflow**.
4. Дождитесь успешного завершения `build` и `deploy`. Адрес после публикации: **https://marat-tibilov.github.io/test-list/**.

После следующих push в `main` сайт обновится автоматически. Workflow сначала запускает тесты и сборку, затем публикует содержимое `dist`. Вручную загружать `dist` в репозиторий не требуется.

Если изменится название репозитория, обновите `base` в `vite.config.ts`. Для собственного домена или репозитория `username.github.io` используйте `/`.

Настройка соответствует [документации Vite для GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages) и [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
